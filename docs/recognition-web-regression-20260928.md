# 2026-09-28 网页识别流程修复与回测

## 修复原因

此前实验脚本已采用新流程，但正式网页的上传入口仍使用旧的 MinerU 链路。
实验结果不能证明网页执行了同一流程；这是接入遗漏。

网页现使用：

1. Gemini 检查所有页的空白和方向。
2. 按方向调整完整页面，Qwen 照录原文；Gemini 独立读取关键字段，用于发现差异。
3. Gemini 一次接收整份原文列表，输出来源映射；程序据此组装 12 列。
4. 对差异有限次补读，保留无法解决的人工确认项。

入口：`Step1Upload → qualityPdfParser → qualityWorkflow → /api/recognize-quality`。
网页不调用 MinerU；仓库中的 MinerU 代码属于历史实验和旧模块。

## 回测方式

- 正式网址：<https://lawtool.cocoaiagent.com/>。
- 独立案件：`回测-20260928-Gemini预检-Qwen原文`。
- 上传公开中文候选样例，通过网页的“下载识别记录”和案件备份冻结实际导入结果后评估。
- 中断后正常重传同一文件，复用已完成的模型响应；新版共享规则重新组装结果。
- 不修改候选标准答案来消除差异，不把人工确认操作作为机器准确率的一部分。

## 已发现并修复的问题

- 旧网页入口与实验流程不一致；现共用流程和提示词，构建校验提示词逐字一致。
- 停止与并行网络错误竞争时可能继续下一个文件；现优先处理取消并停止整个队列。
- 已成功文件要等整个队列结束才保存；现每个文件成功后立即保存。
- 大图在边缘服务器重复 JSON 解析、序列化及校验，实测遇到 Cloudflare 1102；已精简图像传输并保留完整字节校验。
- 资源上限被误报为“文件超过 75MB”；现分开显示，保留重试和续跑能力。
- 部分明确业务字样落在商户栏导致交易类型为空；仅对完整、无歧义且方向一致的字样恢复类型，保留来源。
- “交易地点”及其中英文表头中的明确支付消费字样也保留为用途来源，避免遗漏“支付宝-消费”。
- 金融机构入账只说明支付通道时，原程序直接赋予第三方支付类型；现保留用途待确认，避免把通道当成放款或赎回用途。
- 评估器无法区分部分相同金额、余额的交易；加入完整时间戳的唯一匹配，以及 12 列完全一致记录的逐次计数。保留次数，不能用一条输出抵消两条标准记录，也不宣称已核实物理来源身份。旧评估与修正后的评估均保留。
- 核对任务标题按具体字段显示；类型问题不再被写成“账号或数字”问题。
- 网页保留来源表格的储蓄卡/信用卡性质，避免将储蓄卡中的信用卡还款认成信用卡账单；倒序流水用实际交易顺序计算期初期末。
