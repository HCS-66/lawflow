# 正式网页 PDF 识别流程

## 当前入口

`src/components/Step1Upload.tsx` → `src/parsers/qualityPdfParser.ts` →
`src/recognition/qualityWorkflow.ts` → `/api/recognize-quality`。

1. Gemini 检查所有页的空白和方向。每页提供 A/B/C/D 四个完整方向候选。
   只有模型判空、整页像素近乎空白、PDF 无文字三者同时成立才跳过该页；目录保留该页。
2. 按检查结果旋转完整页，Qwen V3 逐格照录，Qwen Context V1 补充页眉原文。
   Gemini Keys V4 独立读取关键字段，不接收 Qwen 的答案。
3. Gemini Mapping V7 一次接收全部页的原文列表，只输出来源映射；不再读取 PDF。
   与实验相同的 TypeScript 程序从来源组装 12 列、处理重复版式和标出冲突。
4. 结构差异最多补读 6 页，本方账号最多补读 12 页，关键字段差异最多补读 12 页。
   补读仍使用完整页。未解决的问题必须保留为人工待确认项。
5. 原文和模型调用证据保存在独立 IndexedDB 中，按用户、案件、PDF 内容、流程版本、输入哈希隔离。
   同一输入可继续进度；“从头识别”忽略已有结果，保留旧证据。原 PDF 继续由原件存储管理。

网页入口已移除旧 MinerU 调用、银行预分档界面与旁路比较。
仓库仍保留历史实验与旧解析模块供重放；它们不是当前网页的 PDF 入口。

## 提示词与部署

权威提示词位于 `scripts/prompts/`。`npm run recognition:prompts` 生成服务器模块。
构建会检查生成模块是否与实验提示词逐字一致，避免两套提示词各自演进。
生产需要 `GEMINI_API_KEY` 和 `DASHSCOPE_API_KEY`，模型默认与实验相同。
流水、图像和密钥不提交 Git；密钥只放服务端。

## 验证范围

已完成网页流程的单元测试、类型检查、前端构建、Cloudflare Functions 编译。
三份中文样例的冻结结果通过网页数据适配及归一化后，1288 笔的关键文本字段零变化，
待确认量仍为广发 3、建行 28、交行 12 笔。该项是数据适配回归，不能替代网页新调用的端到端回测。

网页实际回测使用独立案件“回测-20260928-Gemini预检-Qwen原文”。
每个文件的“下载识别记录”可以导出页面预检、原文、来源映射和当前待确认项；
案件备份用于冻结浏览器实际导入的结果。文件识别成功后即独立保存，停止操作会取消整个待处理队列。
模型调用缓存按提示词哈希、模型和输入检查；共享组装规则修改后会重新计算，不能把旧的最终结果直接视作新版结果。

旧 MinerU 网页回测不属于这条流程的验收结果。
此前 99.92% / 3.34% / 未提示关键错误 0 为中文候选标准的开发回归，尚非独立盲测认证。
